# 앱 관리 탭

배포가 끝난 뒤의 관리는 대시보드 상단의 **앱 관리** 탭에서 해요. 탭은 배포 여정 → 앱 관리 → 노드 풀 순서로 있어요.
배포를 마친 직후에는 상단 상태 바의 **앱 관리에서 보기** 버튼을 누르면 바로 넘어가고, 방금 배포한 앱 카드가 몇 초간 강조돼요.

화면은 백엔드가 보내는 값만으로 그려요. 업타임, 요청 수, 에러율, 비용, 앱별 런타임 로그처럼 백엔드가 보내지 않는 값은 보여주지 않아요.

- 앱 목록: `GET /projects` (4초마다 갱신)
- 노드 상태와 복제본: `GET /fleet` (15초마다 갱신, 노드 풀이 없으면 표시하지 않음)

## 화면 구성

- **요약 칩**: 운영 중 / 확인 필요 / 배포 중 / 중지 앱 수의 합은 전체 앱 수와 같아요. 노드 풀이 연결돼 있으면 `노드 정상 수/전체 수`도 보여줘요.
- **GitHub push 자동 추적**: 켜 두면 push로 시작된 배포를 자동으로 따라가요. 예전에는 상세 패널의 프로젝트 탭에 있던 스위치예요.
- **앱 카드** (이름순): 상태 배지와 한 줄 설명, 배포 방식(GitHub push · 브랜치 / 수동 배포), 마지막 배포 시각, 배포 횟수, 소스를 보여줘요.
  - **서비스 위치**: 마지막 배포 대상과 지금 서비스 중인 곳을 합쳐 타깃별로 보여줘요. 타깃마다 상태, 공개 URL, 복사, 열기 버튼이 있어요.
  - **Node Pool 복제본**: 노드 풀 앱과 연결되면 복제본별 노드와 CPU를 보여줘요. 이름이 달라도 URL 호스트로 연결해요.
- **노드 상태**: 노드별 정상 / 과부하 / 장애, 코어당 부하·메모리 사용률을 보여줘요. **3D로 보기**를 누르면 노드 풀 탭으로 가요.

## 앱 상태

| 배지 | 뜻 |
| --- | --- |
| 정상 | 모든 타깃이 이번 배포 버전으로 서비스 중이에요. |
| 확인 필요 | 일부 타깃의 배포가 실패했거나 일부만 중지됐어요. 설명에서 어느 타깃인지, 어디서 계속 서비스 중인지 알려줘요. |
| 배포 중 | 새 버전을 올리는 중이에요. 그동안 이전 버전이 계속 서비스될 수 있어요. |
| 실패 | 서비스 중인 곳이 없어요. 로그를 확인하고 다시 배포해 보세요. 요약 칩에서는 확인 필요로 세요. |
| 중지됨 | 사용자가 앱을 내렸어요. 다시 배포하면 살아나요. |
| 중단됨 | 배포를 도중에 멈췄어요. 요약 칩에서는 중지로 세요. |

타깃별 상태도 같은 말을 써요.

- **서비스 중**: 이번 배포 버전이 그 타깃에서 돌아가요.
- **이전 버전 서비스 중**: 이번 배포는 그 타깃에서 실패했지만, 그 전에 성공한 버전이 계속 서비스 중이에요. 다운된 게 아니에요. 카드에 "이번 배포는 실패 · 이전 버전 유지 중"이라고 표시돼요. 백엔드가 이전 버전의 URL을 주지 않는 타깃에는 링크가 없어요.
- **배포 중 / 실패 / 중지됨 / 중단됨**: 앱 상태와 같은 뜻이에요.

## 할 수 있는 일

- **열기**: 이번 배포 버전이 서비스 중인 첫 번째 URL을 새 탭으로 열어요. 이전 버전 URL은 이 버튼에 쓰지 않아요.
- **로그 보기**: 그 앱의 마지막 배포를 배포 여정 탭에서 다시 보여줘요. 배포 기록은 백엔드 메모리에만 있어서, 서버가 다시 시작되면 사라져요. 그럴 때는 "이 배포 기록을 찾을 수 없어요. 서버 재시작이나 보관 한도로 삭제됐을 수 있어요. 다시 배포하면 새 로그를 볼 수 있어요"라고 알려줘요.
- **다시 배포**: 같은 소스, 같은 이름, 같은 브랜치(있으면)와 같은 타깃으로 다시 배포하고 배포 여정 탭으로 가요. 환경 변수는 앱 이름별로 기억돼서 보통 다시 묻지 않아요. 그 앱이 배포 중이거나, 진행 중인 배포를 보고 있으면 버튼이 꺼져요.
- **중지**: 한 번 더 확인한 뒤(**중지 확인**) 컨테이너·터널·Cloud Run 서비스·노드 복제본을 내려요. DB 데이터는 남겨요. 6초 안에 확인하지 않거나 **취소**·Esc를 누르면 취소돼요. 서비스 중인 것이 있고 배포 중이 아닐 때만 보여요.

## 한계

- 복제본 수와 CPU는 **읽기 전용**이에요. 백엔드를 `CLOUDMORPH_FLEET_WATCH=1`로 띄우면 감시 루프가 CPU를 보고 복제본을 늘리고 줄여요 ([노드 풀과 자동 확장](node-pool-fleet.md)).
- 수동 스케일링(`POST /fleet/{app}/scale/{n}`)은 백엔드에 상태 저장형(DB 연결) 앱의 데이터 분리 방지 및 최대 복제본 한도 검사가 누락되어 있어 화면에 노출하지 않고 읽기 전용으로 유지해요. 백엔드 보호 장치가 보강되기 전까지 임의 호출을 권장하지 않아요.
- 노드 풀 이벤트 기록(배포·확장·축소)은 아직 카드에 보여주지 않아요.
