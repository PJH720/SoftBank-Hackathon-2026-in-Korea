# 장애 대응 (incident guard, 담당: 이요환)

떠 있는 앱을 몇 초마다 확인하고, 이상하면 **Jev**가 원인과 첫 조치를 고르고, 감시기가 그 조치를 실행해 회복을 확인한다.
코드는 `backend/app/incident.py`, API는 `GET /incidents`, `POST /projects/{name}/drill`이다.

```
GUARD_INTERVAL(3초)마다  확인 (HTTP + 컨테이너·DB 상태)
    → 이상?  사건(incident)을 연다
    → Jev 1회 (호스팅 약 0.5초, 로컬 clef-flash 약 1.5초): 얼마나 심각한지 · 원인 · 첫 조치
    → 조치: 다시 켜기 · DB 켜기 · 이전 버전으로 되돌리기 · 다른 곳으로 옮기기 · 하나 더 띄우기 · 지켜보기
    → 다시 확인해서 정상이면 해결, 3번 해도 안 되면 사람을 부른다
```

## 판단: Jev

- **Jev**는 TypeSafe의 판정 모델이다. 글을 만들지 않고 질문의 선택지마다 확률을 매긴다 (`POST https://api.typesafe.ai/v1/systemone`).
  `TYPESAFE_API_KEY`를 넣으면 Jev가 판단한다.
- 키가 없으면 **로컬 clef-flash**가 같은 요청에 답한다 (같은 System One API, `scripts/clef-up.sh`). 둘 다 없으면
  틀릴 수 없는 경우만 규칙으로 처리한다 (꺼진 컨테이너는 다시 켜고, 꺼진 DB는 다시 켠다).
- 질문은 한 번에 셋이다: 심각도(5단계), 원인(앱이 멈춤 · 새 버전 문제 · DB 꺼짐 · 과부하 · 연결 통로 끊김 · 플랫폼 장애),
  첫 조치(그 타깃에서 **할 수 있는 것만** 보여 준다). 라벨을 붙인 사건 6개에서 원인 6/6, 조치 6/6을 맞혔다.
  - 선택지 이름을 길게 써서 설명을 빼면 토큰은 줄어도 오히려 느렸다 (점수를 매길 선택지 토큰이 늘어서). 짧은 이름 + 설명을 쓴다.
- 판단에 넣는 것: 증상(HTTP 상태·지연·컨테이너·DB 상태), 컨테이너 로그 마지막 5줄, 이미 해 본 조치, 되돌릴 이전 버전,
  옮길 수 있는 곳. 입력 토큰마다 로컬 모델에서 약 2ms가 들어서 짧게 줄였다.

## 안전장치

- 컨테이너나 DB가 꺼진 것은 확실하니 바로 연다. HTTP 실패만 보이면 **두 번 연속**일 때 연다 (깜빡임으로 사람을 깨우지 않는다).
- 배포 중인 앱(같은 앱 잠금이 잡혀 있거나 `last_status=running`)은 건드리지 않는다. 배포가 컨테이너를 바꾸는 중이다.
- 사건 하나에 조치는 최대 3번. 그래도 안 되면 `escalated`로 사람을 부른다.
- 플랫폼 자체 장애인데 옮길 곳이 없으면 재시작을 반복하지 않고 바로 알린다.
- 다른 곳으로 옮긴 뒤(failover)에는 원래 자리를 10분 동안 다시 알리지 않는다. 옮기기는 같은 이름으로 하는 보통 배포라서,
  저장된 환경변수를 그대로 쓰고 healer의 자가치유도 그대로 돈다. 사람이 보지 않는 배포라 소스 수정 PR은 열기만 하고 묻지 않는다.
- 옮길 곳: 내 컴퓨터·노드 → Cloud Run (`GCP_PROJECT_ID`가 있을 때), 내 컴퓨터 → 노드 풀 (`nodes.json`이 있을 때),
  Cloud Run·노드 → 내 컴퓨터 (Docker가 있을 때).

## 장애 훈련 (`POST /projects/{name}/drill`)

| kind | 하는 일 | 기대하는 대처 |
|---|---|---|
| `crash` | 앱 컨테이너를 `docker kill` | 앱이 멈췄어요 → 다시 켜기 |
| `db_down` | DB 사이드카를 `docker stop` | DB가 꺼졌어요 → DB 켜기 |
| `outage` | 아무것도 건드리지 않고, 감시기가 90초 동안 그 자리를 "연결 안 됨"으로 본다 | 플랫폼 장애 → 다른 곳으로 옮기기 (없으면 바로 알림) |

실측 (M4 Pro, 로컬 clef-flash, `GUARD_INTERVAL=2`, 방명록 앱 + Postgres 사이드카):

| 훈련 | 알아챔 | 판단 | 회복 (알아챈 뒤) |
|---|---|---|---|
| `crash` | 0.9초 | 1.6초 · 앱이 멈췄어요 83% → 다시 켜기 | 2.8초 |
| `db_down` | 1.0초 | 2.1초 · DB가 꺼졌어요 93% → DB 켜기 | 2.2초 (데이터 그대로) |
| `outage` | 1.1초 | 1.5초 · 플랫폼 장애 90% | 옮길 곳이 없어 바로 알림 |

## 환경변수

| 이름 | 기본값 | 뜻 |
|---|---|---|
| `TYPESAFE_API_KEY` | | Jev 키. 비우면 로컬 clef-flash가 대신 판단한다 |
| `JEV_MODEL` | `jev-latest` | Jev 모델 |
| `JEV_BASE_URL` | `https://api.typesafe.ai` | |
| `CLOUDMORPH_GUARD` | `1` | `0`이면 감시하지 않는다 |
| `GUARD_INTERVAL` | `3` | 확인 간격(초) |
