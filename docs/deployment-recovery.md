# 배포 상태와 재시작 복구

API는 계속 `uvicorn --workers 1`로 실행합니다. 배포 명령은 백엔드 호스트의 CLI로 실행하며, 이 변경은 실행 방식을 바꾸지 않습니다.

## fleet 변경 직렬화

등록·확장·축소·삭제·자동 확장·라우터 초기화는 `fleet.json` 옆의 `fleet.lock`을 공유합니다. 상태 읽기부터 라우터 설정 반영과 상태 저장까지 잠금을 유지하므로, 서로 다른 앱의 동시 요청이나 같은 호스트의 CLI/watcher가 오래된 상태로 덮어쓰지 않습니다. 상태 파일은 임시 파일을 fsync한 뒤 원자적으로 교체합니다.

이 잠금은 같은 상태 파일을 사용하는 단일 제어 호스트용입니다. 여러 제어 서버 사이의 분산 잠금이나 라우터와 JSON 파일 사이의 트랜잭션을 제공하지는 않습니다. 긴 SSH 작업 중에는 다른 fleet 변경도 기다립니다.

## readiness와 함수 삭제

배포 성공 판정에는 HTTP 2xx 응답이 필요합니다. health 경로가 404/405일 때만 `/`로 재시도하며, 401/403/5xx나 연결 실패를 홈페이지 성공으로 숨기지 않습니다. 노드 replica도 `/`의 2xx가 필요하므로 API 전용 앱은 해당 경로에 성공 응답을 제공해야 합니다.

`function` 대상의 중지·이동 정리는 저장된 함수 이름, 프로젝트, 리전으로 `gcloud functions delete`를 실행합니다. 이미 없는 함수는 성공적으로 정리된 것으로 취급하고, 권한 오류 등은 호출자에게 전달합니다.

## 작업 체크포인트

기본 저장 위치는 `backend/.cloudmorph/projects-jobs/<deployment_id>.json`입니다. `CLOUDMORPH_PROJECTS_FILE`을 바꾸면 같은 디렉터리에 `<파일 stem>-jobs`를 사용합니다. 프로젝트 파일과 작업 디렉터리를 모두 영속 디스크에 보존해야 합니다.

외부 작업 시작 전에 체크포인트를 작성하고, 단계와 대상별 결과, 리소스 핸들, 종료 상태를 갱신합니다. 파일 권한은 0600이며 원자적으로 교체합니다. 환경 변수 값과 원본 SSE/CLI 로그를 복사하지 않습니다. 소유자, URL, 리소스 식별자와 작업 오류 문자열은 저장하므로 운영 데이터로 보호해야 합니다. 작업 이력은 기존 API 제한과 같이 최근 30개 범위로 유지합니다.

백엔드 시작 시 다음과 같이 복구합니다.

- 완료된 작업의 상태와 대상별 결과를 복원하고 기존 deployment ID로 조회할 수 있게 합니다. 원본 이벤트 전체 대신 결과 이벤트를 재구성합니다. 소유자 접근 제한도 유지합니다.
- 실행 중이던 작업은 체크포인트와 남아 있는 `.deployer/last_result.json`의 성공 결과에서 확인된 핸들을 복원합니다.
- 결과가 불명확한 대상은 중단 오류로 표시합니다. 일부만 성공했다면 `partial_failure`, 성공 대상이 없다면 `failed`입니다. 이전 배포의 알려진 리소스는 보존합니다.
- 외부 명령이나 이동 후 삭제를 자동 재실행하지 않습니다. 사용자가 실제 자원을 확인한 뒤 재배포해야 합니다. 재시작 전 입력 대기도 자동 재개하지 않습니다.
- 기존 버전에서 `running`으로 남은 프로젝트 역시 중단 상태로 전환합니다. 손상된 작업 JSON은 조용히 버리지 않고 시작 오류로 드러냅니다.

이는 작업 상태 복구이며, 중단된 명령을 이어 실행하는 내구성 있는 작업 큐는 아닙니다. 외부 자원 생성과 체크포인트 기록 사이에 프로세스가 종료되면 수동 확인이 필요할 수 있습니다. 클라우드/API/SSH 작업의 exactly-once 실행이나 자동 자원 대조는 보장하지 않습니다.
